## 2. 题目形式：3 个释义 + 「以上都不对」+「不认识」

每题固定 5 个选项：

```text
[ 中文释义 A ]
[ 中文释义 B ]
[ 中文释义 C ]
[ 以上都不对 ]
[ 不认识   ]
```

关键设计：

1. **正确答案不一定是 A/B/C。** 服务端以约 **75%** 的概率把该词的正确释义放进
   A/B/C；剩下 **25%** 的题三个释义全是干扰项，正确答案是「以上都不对」。
2. 正确选项在 `0..3` 上近似均匀分布。对 184 道真实题目的统计：

   | 正确下标 | 0 | 1 | 2 | 3（以上都不对） |
   | --- | --- | --- | --- | --- |
   | 次数 | 41 | 48 | 47 | 48 |

   这正是「75% 放入正确释义并随机打乱 + 25% 全错」的结果：每个下标约 25%。
3. **「不认识」是独立信号**（`selected_index = 4`），不是普通错答。服务端会把它
   记为 `unknown`，扣分力度与「答错」不同（见 §4）。
4. 干扰项多为**同档位、同词性**的其它词释义，偶尔会出现语义相近的干扰项
   （如 `acceptable` 的干扰项 `adj. 适当的`）。

复现代码里的 `make_question()` 完整实现了这套生成逻辑。

## 3. 自适应难度：档位 ≈ 词汇量 / 1000

每道题带一个 `level`（0 起）。从 200+ 道题的观察看：

- `level` 是**词频档位**，每档约 1000 词；档位越高，词越生僻。
- 档位对应的难度阈值约为：

  ```text
  T(level) = 1000 * level + 100
  ```

  例如 level 8 的词大约在「词汇量 8100」附近成为 50% 认识的分界线。
- 第一题固定在 **level 3 或 4**（热身）。
- 之后正常情况下，下一题档位 ≈ `round(score / 1000)`，偶尔向下偏一档。
- **探顶机制**：连续答对 **4 题**后，会跳到当前档位上方 3~4 档（`level + 3/4`），
  并在后续答对时继续上抬（每次 +1~2 档），最多探 6 题；一旦答错或点「不认识」，
  立即结束探顶、回到 `score/1000` 附近。线上偶尔会在探顶失败后 6 题内再探一次；
  复现代码最多探 2 次。

真实轨迹中的例子（`score` 是答完当前题后的分数）：

| 已答 | score | 下一题 level | 说明 |
| --- | --- | --- | --- |
| 1 | 1166 | 1 | 正常 |
| 4 | 3187 | 6 | 连续 4 对，开始探顶 |
| 5 | 4180 | 8 | 探顶中，答对继续上抬 |
| 6 | 4012 | 3 | 探顶遇到「不认识」，回到前沿 |
| 20 | 6920 | 6 | 正常 |
| 21 | 7101 | 7 | 正常 |

这套「热身 → 探顶 → 前沿采样」的策略，比固定分层抽样更快找到词汇天花板。

## 4. 分数更新：Elo / IRT 式估计

这是整个算法最核心的部分。把 `score` 记作 `V`，题目档位记作 `L`，已答题数记作
`n`，则：

```python
p = sigmoid((V - (1000 * L + 100)) / 2500)   # 预期答对概率
K = 2000 / (1 + n / 14) ** 1.5               # 本题步长（随题量衰减）

correct : V += K * (1 - p)
wrong   : V -= K * p
unknown : V -= 0.625 * K * p
```

含义：

- `p` 是 IRT 的**项目特征曲线**：词汇量越高、题目越简单，预期答对概率越高。
- `K` 是**学习率/步长**：初始约 2000 分，随题量按 `n^-1.5` 衰减；答得越多，
  单题影响越小，分数越稳。
- **答对**：按「意外程度」加分——在远高于当前估计的档位上答对，`p` 很小，
  `1-p ≈ 1`，一次能加接近 `K` 分；在简单档位答对，`p` 接近 1，几乎不加分。
- **答错**：按「意外程度」扣分——在简单档位答错（`p` 大）扣得多；在远高于
  当前估计的档位答错（`p` 小）扣得少。
- **不认识**：方向同答错，但权重是 `0.625`，即「不认识」比「选错」略轻。

### 4.1 参数是怎么来的

用 5 组真实接口轨迹（共 150+ 题，覆盖高正确率、低正确率、大量「不认识」三种
策略）做最小二乘拟合，得到：

| 参数 | 拟合值 | 取整后 |
| --- | --- | --- |
| `SCALE` | 2468.75 | **2500** |
| `LEVEL_WIDTH` | 1026.56 | **1000** |
| `LEVEL_OFFSET` | 109.375 | **100** |
| `K0` | 1968.75 | **2000** |
| `TAU` | 13.9375 | **14** |
| `GAIN_EXP` | 1.5 | **1.5** |
| `UNKNOWN_FACTOR` | 0.625 | **0.625** |

拟合值全部落在整数附近，这强烈说明服务端用的就是右侧这组常数。

### 4.2 拟合精度

用取整后的常数回放真实轨迹：

| 轨迹 | 题量 | 最终真实分 | 复现分 | RMSE |
| --- | --- | --- | --- | --- |
| 高正确率（50 题） | 50 | 12923 | 12696 | 122.5 |
| 认识 0~10 档（30 题） | 30 | 10653 | 10699 | 160.1 |
| 5 组轨迹合并（拟合常数） | 150+ | — | — | ≈ 90 |
| 5 组轨迹合并（取整常数） | 150+ | — | — | ≈ 115 |

对 0~13000 的分数而言，1% 左右的误差已经足够复现产品行为。

## 5. 置信区间：`score_interval` 与 `delta`

响应里的：

```jsonc
"score_interval": [583, 1166],
"delta": [-0.5, 0.0]
```

满足：

```text
lower = score * (1 - delta_abs)
delta = [ -delta_abs, 0.0 ]
```

即区间是**单边的** `[下界, 当前估计]`，`delta_abs` 是相对宽度。

观察到的 `delta_abs` 有一条非常规律的「有效样本量」规律：

```python
# 初始 n_eff = 0
if correct:
    n_eff = 1 if n_eff == 0 else n_eff + 0.5
else:                      # wrong / unknown
    n_eff = max(1, n_eff * 0.5)

delta_abs = clamp(0.8 / (2 * n_eff), 0.01, 1.0)
```

- 第一题答对：`n_eff = 1`，`delta_abs = 0.4`（线上约 0.5）；第二题答对：
  `n_eff = 1.5`，`delta_abs ≈ 0.27`（线上 0.25）。整体 RMSE 约 0.035。
- 答错一次：`n_eff` 减半，区间立刻变宽。
- 连续答对：`n_eff` 每两题 +1，区间缓慢收窄。
- 下限 `0.01`：线上最少也会保留 1% 的相对区间。

用这套规则回放高正确率轨迹，`delta_abs` 的 RMSE 约 **0.035**；回放大量错答
轨迹约 **0.071**。

> 注意：这是对区间**行为**的拟合，不是服务端后验分布的严格推导。服务端可能
> 用的是 Beta 后验或粒子滤波，但对外表现与上式高度一致。

## 6. 结果页与覆盖率

- 前端规定**最少答满 20 题**才能看结果；可以继续答，分数持续收敛。
- 结果页显示的「词汇量」就是测试过程中的 `score`，不是结果接口重算的。
- `vocabresult` 额外返回：
  - `position`：超过百分之多少的用户；
  - `coverage`：10 个词表的认识率；
  - `error_words`：答错的词及释义；
  - `last_test`：本次测试的完整状态。

线上的 10 个覆盖率分类：

```text
小学英语 / 英语四级 / 英语六级 / 研究生英语 / 雅思词汇
托福词汇 / GRE词汇 / 哈利波特词汇 / 美剧常用词汇 / 经济学人词汇
```

前 7 个与 ECDICT 的 `zk / cet4 / cet6 / ky / ielts / toefl / gre` 标签基本对应；
后 3 个是欧路自建词表。覆盖率是**模型估计值**：对词表中每个词，用最终 `score`
和该词的档位算 `sigmoid((V - T(L)) / 2500)`，再取平均，而不是「已答题正确率」。

复现代码用 ECDICT 标签实现了前 7 个分类，后 3 个因缺少词表未复现。

## 8. 与仓库现有实现的对比

仓库已有 [`apps/api/app/services/vocab.py`](../apps/api/app/services/vocab.py)，
它用的是**固定分层抽样**：

- 25,000 词按 rank 切成 10 段，每段固定抽 5 题，共 50 题；
- 每段算「认识率」，做单调非增平滑（PAV）后 `Σ 段宽 × 认识率`；
- 用 `GUESS_RATE = 0.25` 压掉四选一蒙对造成的虚高。

欧路用的是**自适应 Elo/IRT**：

| 维度 | 现有实现 | 欧路 |
| --- | --- | --- |
| 选题 | 固定每段 5 题，从易到难 | 按当前估计动态选档，连续答对会探顶 |
| 估分 | 段认识率 × 段宽 | 单点 Elo 更新，`V += K(o-p)` |
| 题量 | 固定 50 题 | 最少 20 题，可无限继续 |
| 单题影响 | 有界（≤ 段宽/该段已答数） | 随 `n^-1.5` 衰减，早期影响大 |
| 蒙对处理 | 认识率 ≤ 25% 记 0 | IRT 的 `p` 天然处理，答错/不认识分别扣分 |
| 覆盖率 | 无 | 10 个词表的模型估计 |

现在欧路算法已作为独立服务 `vocab_eudic.py` 接入，路由按 `algo` 开关分发，
前端协议保持不变；`score_interval` / `level` 已下发，`coverage` 暂未在结果页展示。

### 8.1 本地实现的稳定性调整（2026-11）

真实使用中发现两个问题：首次 12226、后程 36/50 却只有 8130。逐题日志显示，
后者在第一次探顶失败后，直到第 12 题才再次探顶且立即失败；之后第 25–32 题
连对 8 题，但旧规则「第二次探顶必须在首次失败后 6 题内」已经过期，分数被
压在低档位。因此本地实现做了以下调整（与欧路原版行为不同）：

| 项目 | 原实现 | 现在 |
| --- | --- | --- |
| 首题档位 | level 3–4 | level 1–2（高频词热身，避免一上来就是生僻词） |
| 探顶次数 | 最多 2 次，第二次限 6 题内 | 最多 3 次；两次之间至少间隔 8 题，后程连对仍可探顶 |
| 题量上限 | 50 题 | 80 题（50 题后提示可结束，也可继续提高稳定性） |
| 得分估计 | Elo 增量更新，步长随题数衰减，结果受作答顺序影响 | 网格贝叶斯 EAP：取后验均值，给定题目与结果时**与作答顺序无关** |
| 置信区间 | `n_eff` 每错一次减半，区间单边且经常固定 ±40% | 后验 95% 等尾区间（分位数），允许不对称 |

EAP 的实现（501 个网格点：0, 50, …, 25000）：

```python
# 每题把似然乘进后验（对 log 后验做加法）
log_post[i] += log(p)             # 答对
log_post[i] += log(1 - p)         # 答错
log_post[i] += 0.625 * log(1 - p) # 「不认识」，延续原版的软惩罚
# 归一化后
score = Σ θ_i * post_i            # 后验均值
score_interval = [2.5% 分位数, 97.5% 分位数]
```

后验是各题似然的乘积，交换答题顺序不会改变最终后验，因此得分不再受
「先对后错」还是「先错后对」影响。先验取 `N(1000, 3000)` 截断到
`[0, 25000]`：均值低让前几题从高频词缓慢爬升，方差大保证数据能主导估计。
模拟中真实能力 10,000 的用户 80 题后 RMSE 约 550 分；20,000 的用户
不再像 Elo 那样被系统性低估（Elo 约 17,300，EAP 约 19,400）。

## 9. 局限与合规

- **常数是拟合值**：服务端真实常数不可见；本文给出的是与真实轨迹误差 ~1% 的
  一组整数，足以复现行为，但不保证逐位一致。
- **探顶策略是行为拟合**：连续 4 对开始探顶、每次上抬 1~2 档、最多 6 题，这些
  是从多条轨迹归纳出的规则，线上可能还有随机抖动。
- **词表不同**：复现用仓库的 25,000 词 ECDICT 词表，线上词表更大（排行榜最高
  分约 29,116），档位数可能到 29；复现代码把分数上限设为 25,000。
- **覆盖率后 3 类未复现**：哈利波特 / 美剧 / 经济学人词表不在仓库中。
- **合规**：以上分析仅用于互操作/学习目的。接口只应使用自己的账号、低频调用；
  不要批量刷接口或绕过任何访问控制。

## 10. 一句话总结

欧路词汇量测试 = **「3 释义 + 以上都不对 + 不认识」的 4+1 选项题** +
**按 `score/1000` 选档、连续答对 4 题后探顶的自适应选题** +
**参数为 `(2500, 1000, 100, 2000, 14, 1.5, 0.625)` 的 Elo/IRT 分数更新**。
它用 20~50 题就能把词汇量估计收敛到 ±5% 左右，核心代码不到 100 行。
